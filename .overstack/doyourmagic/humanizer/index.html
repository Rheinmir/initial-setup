Humanizer — bộ workflow chạy được

Sáu workflow rời, mỗi cái copy-paste là chạy, sinh từ một lượt khảo sát read-only blader/humanizer. Humanizer không phải thư viện hay CLI: nó là một file prompt Markdown mà agent nạp vào. Vì thế bộ này chia theo hai trục — ai dùng, và gõ lệnh ở đâu.

Bốn cái bẫy đã kiểm chứng — đọc trước khi gõ lệnh

  1. Lệnh chat và lệnh shell không thay thế nhau. /humanizer và /plugin install chỉ chạy trong khung chat của agent; npx skills add chỉ chạy trong terminal. Gõ nhầm chỗ là command not found.
  2. skills remove humanizer --agent '*' không gỡ gì cả, dù --help bảo dùng được '*'. Nó in ■ Invalid agents: * rồi thoát 0. Phải nêu đích danh: --agent claude-code.
  3. Skills CLI copy nguyên repo vào thư mục skill, không chỉ SKILL.md — kéo theo cả scripts/ và .github/. Muốn gọn thì curl một file.
  4. Đừng cài cả hai đường (Skills CLI và plugin Claude Code). Hai bản prompt trùng nhau cùng nạp, cập nhật một bên là lệch.

Nhánh người dùng — dùng Humanizer để chữa văn của bạn

  1. 01Cài bằng shell Terminal

    Đường cài dùng được cho mọi agent hỗ trợ skill. Toàn bộ cờ của Skills CLI đã đối chiếu với --help thật, đường dẫn cài đã quan sát thật sau một lượt cài vào dự án git rỗng, cộng cách curl một file khi bạn không muốn commit rác vào repo. Kèm bảng chọn cách cài theo tình huống, và hai cái bẫy của lệnh gỡ.

    Sinh ra: .claude/skills/humanizer/ · skills-lock.json · 01-install-shell.md

  2. 02Cài làm plugin Chat

    Đường thay thế của 01, chỉ chạy trên Claude Code từ bản 2.1.142. Hai lệnh slash, không đụng terminal, không đẻ file nào trong repo dự án. Giải thích vì sao cú pháp là humanizer@humanizer, cách kiểm manifest bằng claude plugin validate, và vì sao chỉ nên chọn một trong 01 hoặc 02.

    Sinh ra: marketplace + plugin trong cấu hình Claude Code, lệnh /humanizer:humanizer · 02-install-claude-plugin.md

  3. 03Chữa văn bản dán Chat

    Đường dùng chính. Chế độ mặc định trả về ba phần — nháp, phần soi các pattern còn sót, bản cuối — thấy đủ ba là skill đã chạy đúng quy trình. Kèm quy trình 4 bước bên trong, cách đưa mẫu văn để khớp giọng (mẫu văn đè lên cả luật gạch ngang §14), ranh giới cứng "không bịa fact", và bảng 35 pattern theo nhóm để nhắm số hiệu cụ thể.

    Sinh ra: bản viết lại trong chat, nội dung giữ nguyên · 03-humanize-pasted-text.md

  4. 04Chữa file, và nhúng Chat

    Chế độ file ghi đè tại chỗ và chỉ đụng văn xuôi — code block, YAML frontmatter, dữ liệu và đích link phải nguyên vẹn. File này nêu rõ bảng được-sửa / giữ-nguyên, quy trình soi git diff sau khi chạy, chế độ embedded cho PR body và commit message, cách chạy nhiều file, và lý do không có cổng CI cho phía người dùng.

    Sinh ra: file được ghi đè phần văn xuôi + tóm tắt ngắn trong chat · 04-humanize-files-and-embedded.md

  5. 05Chặn sửa quá tay Chat

    Rủi ro lớn nhất không phải sửa thiếu mà là bào mất giọng thật, gỡ mất disclaimer, hay viết lại một câu trích dẫn. Đây là hai hàng rào sẵn có trong SKILL.md — danh sách "không được gắn cờ" và "chi tiết người cần giữ" — cộng câu chat mẫu để gọi thẳng chúng ra, cách khoá phạm vi ngay từ lần chạy đầu, và cách kiểm bằng git diff --word-diff xem có claim nào biến mất.

    Sinh ra: một lượt chạy hẹp hơn, giữ được thứ đáng giữ · 05-tune-false-positives.md

Nhánh đóng góp — sửa chính Humanizer

  1. 06Kiểm và phát hành Terminal

    Repo không có build step, không có test runner, không có package.json — chỉ một validator Python và hai lệnh kiểm bên ngoài, đúng ba lệnh CI chạy. File này liệt kê chín cửa của validator đọc thẳng từ mã nguồn, exit code thật đã tái hiện bằng cách làm lệch version (mọi lỗi đều là 1, fail-fast một dòng), bốn chỗ phải sửa khi thêm một pattern, luật đồng bộ version ba nơi, và trần 500 dòng đang còn 44 dòng dư địa.

    Sinh ra: cây làm việc qua đúng bộ cửa CI trước khi push · 06-contributor-validate-and-release.md
