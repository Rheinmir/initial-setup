Impeccable — workflow bundle

Generated from a read-only exploration of the impeccable repo (npm package impeccable, v3.6.1) — a design skill pack and anti-pattern detector CLI for AI coding agents. Every workflow below links to an immediately runnable .md file sitting next to this page.

Setup

  1. Install and initialize

    01-install-and-init.md

    Run npx impeccable install from your project root to put the skill (and optional edit-time hook) into your AI harness of choice, then type /impeccable init inside the agent's chat to generate PRODUCT.md. Covers non-interactive/scripted install flags and per-harness one-time trust steps (Codex /hooks, Grok /hooks-trust, Cursor Nightly channel).

    consumer
Daily use

  1. Use the 23 design commands

    02-use-design-commands.md

    The full /impeccable <command> reference table (audit, critique, polish, harden, animate, ...) with copy-pasteable examples, typed into your AI agent's chat — not the shell. Includes a suggested first-use order (document → audit/critique → polish) and how to pin a favorite command to its own shortcut.

    consumer

  2. Run the CLI anti-pattern scan

    03-cli-anti-pattern-scan.md

    The standalone, no-AI-agent-required path: npx impeccable detect against files, directories, or live URLs. Documents the real flags (--json, --fast, --no-config), the verified exit-code contract (0 clean / 2 findings / 1 error), and inline impeccable-disable comment suppression.

    consumer
Tuning & operations

  1. Manage detector ignores

    04-manage-detector-ignores.md

    Turn one-off inline suppressions into durable, reviewable, repo-shared waivers with npx impeccable ignores add-rule / add-file / add-value. Includes what a real, lived-in .impeccable/config.json looks like (cross-checked against an actual consuming project on this machine) and the exact .gitignore block for what stays ephemeral vs. tracked.

    consumer

  2. Wire it into your CI

    05-ci-integration.md

    A minimal GitHub Actions step that runs impeccable detect --json and fails the build on findings, plus a variant that always uploads the JSON report. Explicitly separates this from Impeccable's own internal CI (workflow 07) — a common trap when a repo's .github/workflows/ gets copied wholesale into a consumer project.

    consumer

  3. Keep the install updated

    06-keep-impeccable-updated.md

    npx impeccable check / update / link, what re-triggers a harness trust prompt after an update, how to turn on the NDJSON hook audit log for debugging, and how hook-install consent is remembered per developer.

    consumer
Modifying Impeccable itself

  1. Build, test, and extend the tool

    07-contributor-build-and-test.md

    For contributors who cloned the repo itself: the source-of-truth skill format, the provider-factory build (bun run build), the named test suites (bun run test:core, test:detector, ...), the generated-output sync check CI actually gates on, where to add a new detector rule, and the maintainer-only release scripts.
